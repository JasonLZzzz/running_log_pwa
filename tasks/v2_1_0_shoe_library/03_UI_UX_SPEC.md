# 03 — UI / UX 实施规范

目标：新增「鞋库」而不增加每次跑后的填写负担；沿用 V2.0.1 已验收的中文、轻量、移动优先视觉样式、底部三页导航和表单编辑模式。

## 一、页面位置

1. 底部导航继续保持 `记录 / 历史 / 数据` 三项，不创建新的独立主导航页。
2. 在 `数据` 页的「目标管理」附近添加 `鞋库管理` 面板。展示在用鞋清单、`＋ 新增鞋子`、编辑和退役/恢复；已退役默认折叠/隐藏并提供查看入口。
3. 在 `记录` 页**靠前的位置**添加 `本次用鞋` 字段（建议接在训练时间之后）；它是高频字段，不应放入「专项与其他信息」折叠区域。
4. `历史` 页详情中显示 `本次用鞋`，若空则显示「未填写」。列表摘要可增加一条简短鞋子标签，但必须避免手机卡片过高；若有空间冲突，以详情可见、摘要不拥挤为优先。

## 二、记录页选鞋交互

- 默认提供显式选项 `未填写`；新建记录的默认值为 null，不强制选鞋。
- 按钮/单选标签列出在用鞋 `品牌 型号 · 昵称`；支持选择一双并能取消选择回到未填写。
- 当前编辑记录若引用已退役鞋，**必须仍然显示已选项**；可显式展开「显示已退役」，选择过去穿过的鞋进行补录。
- 鞋库为空时，给出友好的「鞋库暂无跑鞋」提示与 `＋ 新增鞋子` 入口；不阻碍其它字段填写与保存。
- 允许在记录页就地 `＋ 新增鞋子`，参考当前新增目标弹窗模式：新建保存成功后自动选中该鞋；新建失败不改变当前记录表单。
- 新增鞋库时，已经编辑了一半的训练记录必须保留原输入，不应因刷新卸载表单或清空草稿。
- 不根据既有备注、活动日期或鞋型自动推断选择；不因退役清掉历史 `shoe_id`。

## 三、鞋库管理

- 每个条目展示 `品牌 型号 · 昵称` + 类型（如有）+ 在用/已退役状态。
- 编辑至少允许修改品牌、型号、昵称、类型、状态、备注；不允许改内部 ID。
- 提供 `退役` 和 `恢复在用`；不提供「删除跑鞋」硬删除入口。
- 新建时品牌/型号必填，昵称默认建议 `1号` 等，可直接覆盖编辑，类型可不填，状态默认在用，备注可不填。
- 对品牌/型号/昵称缺失和同鞋款昵称冲突给出就地可理解的中文验证；输入字段适合 iPhone 键盘、放大字体和小屏。
- 一个已退役条目依然可编辑，历史记录中继续显示；不能把状态变成“已退役后不能使用”的验证错误。
- 文字排版保持此前 `?` 帮助规范：**标题/选项名加粗，解释正文常规字重**；本轮不必为鞋库增加大量 `?` 提示。

## 四、历史补录操作

`历史记录 → 选中记录 → 编辑记录 → 本次用鞋 → 选一双（可含已退役）→ 保存`。

- 补录成功保留原 `record_id`、`created_at` 及非用鞋字段；`updated_at` 按正常用户编辑规则更新。
- 旧记录留空时显示「未填写」，不是「无鞋」。
- 删除训练记录保持 V2.0.1 已验收的二次确认/滚动/焦点逻辑；新增鞋库不能影响该功能。

## 五、移动端与离线体验

- 320px / 390px 视口中不出现横向溢出，长鞋名允许换行；仍可直接点击选鞋按钮。
- 点击保存/退役时显示明确状态，不允许重复提交导致双鞋 ID 或重复记录。
- iPhone 主屏幕 PWA 和当前离线缓存机制保持可用；Service Worker 需要正常缓存新增资源，但不要改变其原本策略，除非有确切必要。
- 「数据」页本地数据安全提示补充：新版备份包含鞋库，旧版备份可导入但没有鞋信息。
